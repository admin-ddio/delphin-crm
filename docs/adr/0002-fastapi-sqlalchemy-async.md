# 0002. FastAPI with async SQLAlchemy 2.0, asyncpg and Alembic

- Status: accepted
- Date: 2026-10-16

## Context and problem statement

The pilot's business logic lives in TypeScript services over Prisma. We need a Python API with typed
models, strong validation, first-class OpenAPI and safe migrations on PostgreSQL 16.

## Considered options

1. FastAPI + Pydantic v2 + SQLAlchemy 2.0 (async, typed `Mapped[]`) + asyncpg + Alembic
2. Django + DRF
3. FastAPI + SQLModel

## Decision outcome

Option 1. FastAPI generates the OpenAPI the frontend is built from. SQLAlchemy 2.0 gives full control
over the PostgreSQL features the pilot relies on (partial unique indexes, triggers, citext). Alembic keeps
migrations explicit and reviewable.

### Consequences

- Strict layering (router → service → repository → models) is enforced by import-linter.
- One transaction per request (`db.session.get_session`); repositories never commit.
- Autogenerated migrations must still be reviewed by hand. `alembic check` runs in CI.
